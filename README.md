## 🎯 SRE Principles I Live By

- **Service Level Objectives (SLOs)**: Define clear reliability targets that balance user happiness 
  with engineering velocity, ensuring we build systems that are reliable enough without over-engineering.
- **Error Budgets**: Use the difference between 100% uptime and our SLO target as a budget for 
  taking risks, enabling innovation while maintaining reliability commitments.
- **Toil Reduction**: Automate repetitive operational work to free up time for engineering projects 
  that improve system reliability and scalability.
- **Blameless Culture**: Foster psychological safety through blameless postmortems that focus on 
  system improvements rather than individual blame, accelerating learning from incidents.
- **Chaos Engineering**: Proactively inject failures in controlled environments to build confidence 
  in system resilience and uncover weaknesses before they impact users.

## 🚀 Featured Projects

### [SLO & Error Budget Monitor](https://github.com/Vamsi3556/slo-error-budget-monitor)
**Problem it solves**: teams define SLOs on paper but rarely track error-budget burn in real
time, so incidents get noticed late and postmortems happen reactively (if at all).
**What it does**: synthetic-checks a set of services on a schedule, computes rolling uptime and
error-budget burn against an SLO target, and automatically files structured GitHub Issues - an
immediate blameless-postmortem template on failure, and a proactive warning issue before the
budget is fully burned, auto-closing once recovered.
